================================================================================
                    SOFTWARE SPECIFICATION REQUIREMENTS (SSR) DOCUMENT

Project Title: TradeRelay - Team-Based TradingView Webhook Automation Platform

Document Version: 2.0
Last Updated: December 2024
Target Audience: Development Team, Stakeholders
Status: Ready for Development

================================================================================
                                   OBJECTIVE
================================================================================

To develop a secure, team-focused web application that listens to webhook alerts 
from TradingView and executes trades on platforms such as Bybit (crypto), 
Binance (crypto), and Alpaca (stocks), designed for small trading teams of 4-10 
members with comprehensive analytics and admin controls.

================================================================================
                               1. TECHNOLOGY STACK
================================================================================

Frontend:
• HTML5, CSS3, JavaScript
• Bootstrap 5
• Chart.js for analytics and charts

Backend:
• Django 4.x (Python)
• Django-allauth for authentication and social login
• Django-extensions for enhanced functionality

Trading API Integrations:
• Bybit via `pybit` (crypto trading)
• Binance via `python-binance` (crypto trading)
• Alpaca Markets via `alpaca-py` (US stocks/ETFs)

Data Storage:
• PostgreSQL (Relational Database)
• Redis (Caching and session management)

Deployment:
• Docker
• Azure App Service
• Azure Database for PostgreSQL
• Azure Key Vault for API credentials

================================================================================
                          2. TEAM-BASED ACCESS MODEL
================================================================================

Team Structure:
• Maximum 10 users per TradeRelay instance
• Invite-only registration with admin approval
• Role-based access (Admin, Trader)
• Individual user limits and permissions

User Limits (Per Trader):
• 10 webhook endpoints per user
• 1,000 trades per day per user
• Full platform access (Bybit + Binance + Alpaca)
• 365-day analytics retention

Admin Controls:
• User approval/suspension
• Individual limit management
• Team-wide settings
• Platform enable/disable
• Analytics oversight

================================================================================
                             4. DATABASE SCHEMA
================================================================================

User Management Models:

UserProfile:
- user (OneToOne with Django User)
- status (pending, active, suspended, inactive)
- avatar (ImageField)
- max_webhooks (default: 10)
- max_daily_trades (default: 1000)
- preferred_platforms (JSONField)
- total_trades, successful_trades
- last_trade_at, last_active

UserInvitation:
- invitation_id (UUID)
- email
- invited_by (ForeignKey)
- status (pending, accepted, expired)
- expires_at
- role, message

TradingSession:
- user (ForeignKey)
- session_id (UUID)
- started_at, ended_at
- trades_count
- platforms_used (JSONField)
- total_pnl, best_trade, worst_trade

Webhook & Trading Models:

WebhookEndpoint:
- user (ForeignKey)
- webhook_id (UUID)
- name (CharField: user-defined)
- secret_key (CharField)
- is_active (BooleanField)
- platform_config (JSONField)
- usage_count, last_used

Trade:
- user (ForeignKey)
- webhook_endpoint (ForeignKey)
- platform (bybit/binance/alpaca)
- symbol, side, quantity, price
- status (success/failed)
- profit_loss (DecimalField)
- execution_time, timestamp

Analytics:
- user (ForeignKey)
- metric_type, period
- value (DecimalField)
- calculated_at

Team Settings Model:

TeamSettings:
- team_name (CharField)
- max_team_size (default: 10)
- require_admin_approval (BooleanField)
- enabled_platforms (JSONField)
- default_limits (JSONField)
- notification_settings (JSONField)
- analytics_retention_days (365)

A. Webhook JSON Format Examples:

For Bybit (Crypto):
{
  "platform": "bybit",
  "symbol": "BTCUSDT",
  "side": "buy",
  "qty": 0.01,
  "order_type": "market"
}

For Binance (Crypto):
{
  "platform": "binance",
  "symbol": "BTCUSDT",
  "side": "buy",
  "qty": 0.01,
  "order_type": "market"
}

For Alpaca (Stocks):
{
  "platform": "alpaca",
  "symbol": "AAPL",
  "side": "buy",
  "qty": 10,
  "order_type": "market"
}

B. Environment Variables Required:

# Django Settings
SECRET_KEY=your-secret-key
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1

# Database
DB_NAME=traderelay
DB_USER=postgres
DB_PASSWORD=your_password
DB_HOST=localhost
DB_PORT=5432

# Social Authentication
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret
GITHUB_CLIENT_ID=your_github_client_id
GITHUB_CLIENT_SECRET=your_github_client_secret

# Trading APIs
BYBIT_API_KEY=your_bybit_key
BYBIT_API_SECRET=your_bybit_secret
BYBIT_TESTNET=True

BINANCE_API_KEY=your_binance_key
BINANCE_API_SECRET=your_binance_secret
BINANCE_TESTNET=True

ALPACA_API_KEY=your_alpaca_key
ALPACA_SECRET_KEY=your_alpaca_secret
ALPACA_BASE_URL=https://paper-api.alpaca.markets

# Team Settings
MAX_USERS=10
REQUIRE_ADMIN_APPROVAL=True
INVITE_ONLY=True
